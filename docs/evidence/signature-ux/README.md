# Signature UX regression evidence

Generated by `scripts/gui_signature_acceptance.sh` against the actual Linux debug and optimized release
GUI on a dedicated Xvfb display and a disposable profile. The suite creates typed
and drawn handwriting, saves one for reuse, resizes with a corner handle, undoes
and redoes the resize, restores automatic size, fits a reused signature into a
dragged box, saves PDFs, checks active annotation metadata with qpdf, and reopens
the document in a second application process. `results.json` contains measured
PDF-point dimensions. The aspect ratio remained unchanged through resizing.

Screenshots show the plain-language creation and certificate dialogs, selection
controls, and handwriting after reopen. The certificate dialog is opened but
this GUI suite does not create an identity or submit a cryptographic signature.
The fixture validation CLI separately signs a PDF containing handwriting without
an additional visible stamp, verifies that PDFium pixels on the handwriting page
remain identical, and checks signature integrity. Poppler also rendered identical handwriting-page
PNGs before and after certificate signing; pdfsig independently
reported Signature is Valid and qpdf found no structural errors.

This is a focused signing UI iteration, not full GUI acceptance or Windows desktop
validation. Manual image cropping, opaque-background removal, and filling an
existing cryptographic signature field are still unsupported. There are no
personal documents, production identities, or private keys in this evidence.
